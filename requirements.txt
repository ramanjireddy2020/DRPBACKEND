# Open Babel: this wheel ships BOTH the `obabel` executable (into Scripts/) and
# the in-process `openbabel.pybel` bindings. docking_service tries the
# executable first and falls back to the bindings, so conversion still works on
# a host that refuses to execute unsigned binaries (see below).
openbabel-wheel
#
# NOT pip-installable — AutoDock Vina itself. `pip install vina` builds from
# source and needs Boost + a C++ toolchain (no Windows wheel). Official
# prebuilt binaries, including a Windows one, are published per release:
#   https://github.com/ccsb-scripps/AutoDock-Vina/releases
#   linux_x86_64 | linux_aarch64 | mac_x86_64 | mac_aarch64 | win.exe
# Drop it in DRP_Main/bin/ (searched automatically) or set SCREENING_VINA_PATH.
#
# NOTE for locked-down Windows workstations: endpoint-security policy here
# denies execution of both vina.exe and obabel.exe with `WinError 5 / Access is
# denied`, even though the files are present. Conversion survives via the
# in-process bindings; docking does not, since nothing substitutes for Vina.
# That needs an allowlist entry for the binary path, or a Linux host / the
# Databricks job. /screening/health reports this as
# `reason: "blocked_by_policy"` rather than as a missing dependency.
